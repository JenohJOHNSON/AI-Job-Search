# Provider access matrix

Research date: **7 September 2026**. Primary documentation and current provider terms were reviewed before implementation. Reliability below is an engineering assessment of the documented access method, not a measured service-level guarantee. An accessible webpage or an undocumented endpoint does not establish permission to automate it.

The application uses the first available **permitted** strategy. A denied request, CAPTCHA, authentication failure, or explicit restriction stops extraction for that source; it never triggers a proxy or browser attempt to evade the restriction. Disabled providers remain visible with an explanation and do not stop other providers.

## Initial integration choices

1. Implement public Greenhouse, Lever, and Ashby board reads so the system can collect real jobs without paid extraction services or candidate credentials. Employer identifiers are configuration, not fabricated sample listings. Search filters run on normalized records because these APIs expose individual boards, not the entire French labor market.
2. Implement France Travail's official search API for broader French coverage. Keep it disabled until the operator provides API credentials. A fixture test proves mapping behavior; only a successful authorized live call proves account configuration.
3. Support bounded, explicitly permitted company pages with JSON-LD. Configure specific URLs and approved hostnames. Validate public DNS addresses and redirect destinations, cap bytes/time, sanitize HTML, and obey robots rules.
4. Show all requested providers in settings, including unavailable ones. An enabled toggle cannot override an unsupported capability or missing agreement. No Apify actor, proxy, stealth browser, or CAPTCHA service is a default fallback for restricted sites.

## Strategy and provenance requirements

The TypeScript contract should provide `search`, `fetchDetails`, `normalize`, and `healthCheck`; return a validated shared job schema; and keep persistence, deduplication, ranking, and notifications outside adapters. Each record should preserve provider ID, source job ID, source URL, chosen extractor, and bounded raw metadata. An absent date or salary must stay unknown. Do not replace a missing publication date with discovery time or annualize an ambiguous salary.

Strategy fallback only applies to equivalent permitted extractors on the configured host or API. Retry transient network/429/5xx failures with finite exponential backoff and respect `Retry-After`. Treat `AUTH`, `BLOCKED`, parser validation failure, and unsupported configuration distinctly. A failed source is recorded in the provider run and skipped; the remaining pipeline continues.

## Verification policy

Live integration verification is opt-in and limited to explicitly configured public employer boards or a credentialed France Travail account. CI uses synthetic fixtures, including French and English postings, null salary, multi-location/remote records, malformed payloads, and outages. Production never substitutes fixtures when an upstream source fails.

Implementation statuses in this file describe the initial pre-code research checkpoint and must be updated as adapters and smoke tests are completed. Optional browser/proxy/service strategies are extension points, not claims of shipped integrations. Re-check provider terms and API docs before adding or repairing an adapter.
